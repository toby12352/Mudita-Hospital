Mudita Hospital — Risk & Continuity Answers

For installers and the hospital director. Staff day-to-day: cheat sheet. Crash laminate: crash / restore card. Deploy: DEPLOY.md.

Offline LAN clinic app: one always-on Windows server PC holds all data (C:\MuditaHospital\Server\data\mudita.db); clinic PCs run thin clients over HTTP port 8080. No internet required after install.

1. Could the software fail to meet “hospital standard”?

Built for OPD billing, OT case-cart, pharmacy stock, and cash reports—not a certified medical device, full EHR, or life-support system.

What people often meanWhere Mudita stands
Reliable day-to-day billing & stock for a small/mid clinicDesigned for this (watchdog, WAL SQLite, roles, print)
Regulatory / ISO / MoH certificationNot claimed
Clinical decision support that could kill if wrongOut of scope — clinical judgment stays with staff

Reduce risk: pilot with Training mode + shadow paper 1–2 weeks; reconcile daily cash and stock; keep paper/Excel fallback until numbers are trusted.

2. Calculation off — hospital loses money?

  • Daily cash report vs cash drawer — every day.
  • Low stock / near expiry vs shelf — weekly.
  • Audit Doctors / Services / Pharmacy prices (master-data errors are common).
  • Voids need a reason; OPD vs OT stock restore rules differ.

Human reconciliation is the control. Backups help investigate; they do not refund cash.

3. Installer overseas — app crashes?

Built-in: MuditaHospitalAPI + watchdog; clients show Server offline / Retry.

Not built-in: cloud monitoring or remote control without hospital help.

  1. Server on? Green Server connected?
  2. http://127.0.0.1:8080/api/health on server
  3. Restart scheduled task (FIELD_INSTALL_FAQ)
  4. Admin → Restore from backup / USB
  5. Call support with photos

Agree remote desktop (if allowed) before long absence.

4. How long without developer supervision (one trained staff)?

HorizonRealistic if…
Days–weeksBill / restock / print; server on; backups run
1–3 monthsWeekly USB copy done; Admin known; cheat sheet laminated
LongerSecond trained person + written restore steps + support on call

One trained person is a single point of failure. Knowledge and backup discipline expire — the app does not.

6. Non-technical users?

Yes for desk work after short training (EN/မြန်မာ, Help, cheat sheet). No for zero training — Server IP, roles, OT reconcile, Backup/Restore need onboarding (~half-day desk; Admin longer).

7. Trained person quits before replacement is trained?

  • Laminate cheat sheet at every desk.
  • Two Admins (or sealed emergency password with director).
  • Training mode (DEMO- / [TRAINING]) for practice.
  • Handoff: Server IP, USB location, support contact on crash card.

8. Data gap?

Missed entry, void, wrong adjust, or backup gap. Detect with cash/stock counts. Restore only recovers what was backed up. Physical recount is the stock safety net.

9. Software destroyed/uninstalled — still need data?

  • uninstall-server.ps1 without -RemoveData can leave data.
  • -RemoveData wipes DB/backups — avoid unless intentional.
  • Survival: USB backups\ → reinstall server → Restore. Clients never store the hospital DB.

10. Data lost somehow?

Only from backups (24h auto + weekly USB). No cloud replica. If every copy is gone, history cannot be recovered. Prevention is mandatory.

11. Transfer to a new device?

  1. Backup now; copy backups\ to USB.
  2. Install server on new PC; set static IP.
  3. Admin → Restore; update every client Server IP; smoke-check.

12. Secure unless someone physically steals it?

No — do not use that mental model.

Have: role logins, hashed passwords, sessions, idle lock, Admin-only backup; LAN-only by default.

Do not have today: HTTPS/TLS on LAN; encryption at rest for mudita.db; protection against unchanged defaults or USB walk-away.

Trust model: closed wired LAN + changed passwords + locked server + confidential USB + locked Windows accounts. Clinic-grade LAN security — not “only physical theft.”

Leave-site checklist

  1. Pilot 1–2 weeks parallel with paper; daily cash match
  2. Change defaults; named users; two Admins
  3. Demonstrate Backup → USB → Restore; staff repeat once
  4. Leave cheat sheet + crash card + contact
  5. Agree remote tool (if any) and who powers the server
  6. Lock USB backups; label hospital + date
  7. Fill blanks on the crash card
